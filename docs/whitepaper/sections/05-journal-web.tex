\section{A Web of Resources}

The conventional Web organizes interaction around sites, origins, URLs, resources, representations, links, and clients~\cite{Jacobs2004webarch,BernersLee2005uri}; the Synchronic Web gives each term a historical analogue. A journal resembles a site with its own administration and evolving state, its root supplies an origin for interpretation, a path identifies a resource from that root, and a committed head selects the historical view in which resolution occurs. The returned representation may be bytes, an expression, a partial proof, or a self-encoding object. Resource identity has two dimensions: a path such as \texttt{components/17/\allowbreak inspection} gives continuity across versions, while a digest identifies the exact state found there at one head. A client can therefore request the current resource, resolve the same path at an earlier index, or cite one particular representation by digest. Paths cross semantic as well as structural boundaries: one segment may enter a tree, another an object, and another a foreign history retained beneath a bridge, with each object interpreting its documented portion while preserving end-to-end evidence. Because historical states remain addressable, ordinary links embedded in representations can cite a persistent version rather than only a moving current resource; relative references remain ordinary URI references interpreted by the client against the selected resource~\cite{Rivest1996sdsi,Mazieres1998path}. Every journal thus induces a distinct coordinate system over local and reachable foreign state; a bridge segment records the relationship through which a foreign coordinate became reachable, a historical index selects the committed viewpoint, and content-derived identifiers name exact representations~\cite{Haber1997secure,Kuhn2014trusty,Zhang2014named}. A prior state becomes part of the ordinary address space, partial evidence can travel as its representation, and clients can distinguish unknown structure, empty structure, unavailable data, policy denial, and unreachable endpoints.

\section{Access Across the Web}

Most useful data begins in an operational form---relational rows, object records, files, indices, transactions, or application-specific graphs---while an addressable network form favors stable resource boundaries, linking, selective transfer, citation, and plural retention. \Cref{tab:data-forms} presents these as complementary views. A Web projection maps selected operational state into journal resources under a contract covering deterministic encoding, paths, resource boundaries, progress manifests, correction, privacy, deletion, and replay. The source can remain load-bearing while an asynchronous projection supplies historical evidence, and mature clients may gradually let selected projected resources assume an operational role.

Local paths provide access within one journal; federation extends access through exact journal objects already committed beneath those paths. A working route follows the latest committed object at each hop and translates receiver-local bridge aliases through each committed \texttt{remote-name}; missing material may fill a stump only when its digest remains fixed, and a live continuation never substitutes a newer embedded checkpoint. For \texttt{resolve}, a separate historical cursor supplies one origin index plus one index per route hop; those indexes are interpreted against the working route's ordered journal names to identify the content being read, while the working route supplies current authentication and endpoint context. The implemented signed application surface is exactly \texttt{get}, \texttt{set!}, and \texttt{resolve}; direct \texttt{route}, constrained \texttt{trace}, \texttt{info}, \texttt{size}, and \texttt{synchronize!} remain bridge/control protocol. Finite routes may revisit a journal, with terminal authorization deciding whether the resulting principal is permitted. \Cref{fig:federated-invocation} shows the exact-object handshake and direct terminal invocation:

\begin{itemize}
  \item \textbf{Exact forward route.} From A's selected committed head, each hop follows the nested journal object already stored there until A reaches the exact B object containing B's root audience, interface endpoint, and index/digest context.
  \item \textbf{Receiver-relative return.} B returns a partial object at that same historical B head containing B's reverse route to A's interface key and root-sequence context; A requires its index, digest, and reverse sequence to agree with the B object already committed beneath A's forward route~\cite{dinh2025identity}.
  \item \textbf{Direct application call.} A signs and sends the B-rooted object with a \texttt{get}, \texttt{set!}, or \texttt{resolve} invocation directly to the committed canonical endpoint; intended production deployments use HTTPS. B matches the raw supplied-object digest against its own history before evaluation, reconstructs the canonical bridge principal, checks audience and signature, and authorizes the request locally. Intermediaries see public route/control metadata while the private function, path, arguments, and value travel only on the final connection.
  \item \textbf{Result and retention.} Live \texttt{get} results and \texttt{set!} acknowledgements receive operational assurance from the direct connection to the committed endpoint; \texttt{resolve} additionally returns proof that A verifies against the selected historical B object. A may then retain that proof through a separate origin-local \texttt{pin!} over the full bridge/history path.
\end{itemize}

The records implementation and Scheme tests cover exact-object multi-hop routing, descriptor/key/endpoint/audience binding, terminal authorization, the narrow function allowlist, origin verification, local proof retention, self-returning finite routes, and rejection of local-only operations. Multi-node HTTP and browser QA has exercised direct and multi-hop \texttt{get}, \texttt{set!}, and \texttt{resolve}; ancestor projection and unauthorized-child denial; proof round-trip and origin-local pinning; outage recovery; and bridge deletion and re-establishment. \WIP Remaining acceptance and protocol work includes real TLS, endpoint cutover beyond operational overlap or forwarding, auto-accept egress policy, incorporation-receipt retrieval, and broader durable application response receipts.

\section{Identity as History}

Identity, integrity, and authorization form a continuous historical path. In the current implementation, a stable root key signs committed descriptor state containing the journal key, interface key, name, and canonical endpoint and remains the identity bound by bridges; bridge history is the trust anchor, while \texttt{info} supplies convenience metadata. Interface keys may evolve through later root-signed synchronized heads. \WIP The intended lifecycle instead binds bridges and invocation audiences to a stable randomized journal identifier while root signing keys evolve through predecessor-authorized lineage; this remains design rather than implementation. For an invocation, the origin supplies an explicit scalar---its journal, a locally authenticated user, or a public caller---which the exact route turns into a receiver-relative principal such as \texttt{(*bridge* alice *state* carol)}. The terminal-local \texttt{key-index} records the terminal history index whose committed bridge object authenticated that origin key, and an authorization rule may constrain it relative to the terminal's current index; it is a local historical key window rather than an origin freshness marker. Terminal rules grant path-scoped \texttt{get}, \texttt{set!}, and \texttt{resolve} permissions only. Administrators are local \texttt{(*state* name)} principals, and bridge management, configuration, authorization changes, batching, pinning, secrets, windows, and root-plane calls remain local. A local administrator's \texttt{bridge!} performs implemented two-phase orchestration by synchronizing the peer before re-entering the authenticated local mutation with prepared data. Replay is intentionally accepted: \texttt{set!} keeps ordinary repeatable-write semantics, transport retries may repeat it, and applications add identifiers, idempotency, or state preconditions when their domain requires them. Across all cases, the committed route identifies the origin, its signature authenticates the invocation and optional user attestation, and terminal state maps the resulting principal to permitted operations.

\section{A Web of Viewpoints}

A mature Synchronic Web begins from the journal a person, organization, or application chooses to trust locally. That journal is simultaneously a store, historical memory, policy engine, and gateway into other histories; following an ordinary link is a client action from this viewpoint, with the target resolved through the same historical addressing and local policy as any other resource. Discovery supplies candidate journals, endpoints, resources, and routes through descriptors, indices, social exchange, existing links, and out-of-band knowledge. Historical continuity lets candidates update endpoints and interface keys while preserving identity, local policy promotes selected candidates into bridges or trusted routes, and the journal's graph gradually records both reachable resources and the relationships through which they became meaningful. Clients make this architecture usable. A browser, filesystem, gateway, projection worker, or inspection tool chooses roots and heads, fetches and merges evidence, invokes objects, enforces policy, and applies retention intent; routine interactions present ordinary resources while audit views expose paths, signatures, slices, and receipts. Application vocabularies such as W3C PROV, domain schemas, scientific objects, and future protocols remain resources above the generic history and integrity layers~\cite{Moreau2010open,Moreau2013prov}, with definitions that evolve through self-encoding objects and relationships that can identify resources across journal boundaries. \WIP Browser behavior, discovery indices, broader durable response assurance, selective disclosure, root recovery, and general projection contracts define much of the remaining path, guided by one principle: every resource is reached from a chosen viewpoint, every historical claim carries its evidence, and every act of trust belongs to the journal that relies on it.
